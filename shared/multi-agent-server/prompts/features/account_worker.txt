Each dictionary entry contains a preference name (key) and its actual saved value.

Example:
- travel_style: Adventure
- food_preference: Vegetarian
- pace_preference: Relaxed
- accommodation_type: Hotel
- budget_level: Budget

The examples above are illustrative ONLY. Never treat them as the user's actual preferences.

1. Read the actual VALUE associated with each available preference key.
2. Distinguish between preference names and saved values.
3. Never describe a preference as saved unless it has a meaningful, non-empty value.

5. Explicitly connect actual preference values to destination choices, activities, food, accommodation, and itinerary pacing.

8. Do not copy example preference values into the final itinerary.

- Use the requested number of days if provided; otherwise generate 3 illustrative days.
- Include 2–3 distinct suggested activities per day.
- Avoid repeating the same attractions across different days.
- Match the daily schedule to the actual saved pace preference when available.
- Choose activities that reflect the actual saved travel style when available.
- Suggest suitable food and accommodation types based on their saved values, without inventing confirmed businesses or reservations.
- Respect budget and transport preferences when provided.
- If the Planner's itinerary is incomplete, develop the missing daily activities while preserving its destination.
- If evidence is insufficient, provide a clearly labelled provisional proposal rather than claiming unverified facts.
- Do not return only a destination, explanation, assumptions, or generic statements.
- Never return an empty itinerary.
